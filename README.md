# DevTool plugin: container-manager

Optional plugin for [DevTool](https://github.com/DianaSensei/developer-desktop-utils),
installable at runtime (Settings → Extensions → paste a manifest URL) instead
of being compiled into the main app. Forked from the `devtool-plugins`
skeleton (`main` branch) — see that branch's README.md for the overall
branch layout and why plugins live on their own branch each.

- `plugins/container-manager/ui/` — the plugin's React components.
- `plugins/container-manager/entry.tsx` — the single default-export wrapper
  Vite builds into `dist/bundle.mjs` (the format `kind: "plugin"` manifests
  require — see developer-desktop-utils's `docs/plugin-sdk/05-external-install.md`).
- `plugins/container-manager/sidecar/` — a standalone Rust binary crate
  (`devtool-svc-container`), speaking the same JSONL-over-stdio protocol as
  any other Tier-B DevTool sidecar.
- `plugins/container-manager/manifest.plugin.json` / `manifest.service.json`
  — templates. CI (`.github/workflows/release.yml`) fills in
  `version`/`entry`/`integrity` (or `targets`) and publishes the filled
  versions as GitHub Release assets.
- `shared/` — vendored from `main`; pull skeleton updates with
  `git fetch origin main && git merge origin/main`.

## Building locally

```bash
npm install
npm run build            # -> plugins/container-manager/dist/bundle.mjs
npm run typecheck
npm test
```

## Styling — the host owns the stylesheet

A plugin bundle is **JavaScript only**: `scripts/makePluginConfig.mjs` builds
one ESM file and emits no CSS, and everything on screen is styled by the host
app's already-compiled Tailwind sheet. That sheet is generated by scanning the
host's own `src/**` (`tailwind.config.js` → `content`), which never includes
this repo — so a class written *only* here lands in the DOM with no rule
behind it and is silently a no-op.

Named utilities (`flex`, `p-2`, `text-xs`, `h-ctl`, the design-system tokens)
are safe in practice: the host app uses the same kit, so the rule exists.
**Arbitrary values are not** — `h-[68vh]`, `max-h-[70vh]` and friends each
compile to their own rule, emitted only if some host file happens to spell it
character-for-character.

So: express viewport- or pixel-exact sizing as an inline `style`, which no
build step can drop.

```tsx
// no rule in the host sheet unless a host file also writes it
<div className="flex h-[68vh] max-h-[calc(100vh-13rem)] flex-col" />

// always applies
<div className="flex flex-col" style={{ height: '68vh', maxHeight: 'calc(100vh - 13rem)' }} />
```

`ui/hostCssClasses.test.ts` enforces this for the sizing and layout prefixes,
where a dropped rule means an unusable window rather than a cosmetic nudge:
the container log dialog's box lost its height this way, grew with every line
that streamed in, and ran off both ends of the screen with its own toolbar out
of reach. Its allowlist holds the arbitrary sizing classes verified to exist
in the host's sheet today; extend it only after checking the host for that
exact spelling.

## Releasing

Push a tag matching `container-manager-vX.Y.Z`. `.github/workflows/release.yml`
builds the bundle, cross-builds the sidecar for every target triple
DevTool's installer understands, computes SHA-256 for each artifact, fills
in the manifest templates, publishes everything as a GitHub Release, and
merges this plugin's entry into the aggregated `catalog.json` on `main`
(without touching any other plugin's entry there). The site's plugin list
reads that file from `main` directly.

## Installing this plugin

In DevTool: **Settings → Extensions**, paste the manifest URL (from
`catalog.json`'s `pluginManifestUrl` on `main`), install, then do the same
with `serviceManifestUrl` for its sidecar, and restart the app.
